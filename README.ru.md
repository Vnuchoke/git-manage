# Git Manage

[![CI](https://github.com/GuoChen-thlg/git-manage/actions/workflows/ci.yml/badge.svg)](https://github.com/GuoChen-thlg/git-manage/actions/workflows/ci.yml)
![version](https://img.shields.io/badge/version-0.0.1-blue)
![license](https://img.shields.io/badge/license-Apache%202.0-blue)

**Git Manage** — кроссплатформенный графический инструмент для управления Git, распространяемый в виде расширения [OpenChamber](https://docs.openchamber.dev/sdk/). Его интерфейс во многом основан на окне Git в IntelliJ IDEA. Благодаря этому разработчики, привыкшие к работе с Git через IDE, могут сразу пользоваться знакомыми возможностями: управлять ветками, просматривать историю коммитов и сравнивать изменения.

## Возможности

- **Управление ветками**: группировка локальных и удалённых веток, добавление часто используемых веток в избранное, создание, переименование, переключение и удаление. Перед удалением положение ветки автоматически сохраняется, поэтому случайно удалённую ветку можно восстановить одним нажатием прямо из уведомления. При удалении неслитых веток выводится явное предупреждение, а текущая ветка защищена от ошибочного удаления
- **История коммитов**: список коммитов с графом истории и подробной информацией; поддержка распространённых операций, включая cherry-pick, revert и stash
- **Сравнение изменений**: просмотр различий на уровне отдельных файлов и коммитов, наглядное управление областью подготовленных изменений (staging area)
- **Гибкая фильтрация**: комбинирование фильтров с учётом регистра, по регулярным выражениям, веткам, авторам, датам и путям к файлам. Для путей предусмотрен множественный выбор в древовидном представлении, как в IntelliJ IDEA
- **Многоязычный интерфейс**: поддержка 12 языков, включая китайский, английский, японский, корейский, немецкий и французский. Язык интерфейса и формат дат автоматически подстраиваются под системные настройки. Подробнее — в [документации по интернационализации](packages/openchamber/I18N.md)

## Установка

В OpenChamber откройте **Настройки → Расширения**. Доступны три способа установки.

### 1. Установка из ZIP-архива

Скачайте архив `git-manager-<version>.zip` нужной версии со страницы [Releases](https://github.com/GuoChen-thlg/git-manage/releases). Выберите его в настройках расширений либо перетащите в область установки.

### 2. Установка из папки

Этот способ подходит для локальной разработки. Запустите сборку в режиме наблюдения: при изменении исходного кода собранные файлы будут обновляться автоматически.

```sh
pnpm install
pnpm dev        # Следить за изменениями исходников и собирать файлы в packages/openchamber/dist
```

При установке выберите каталог `packages/openchamber`. OpenChamber загружает собранные файлы из `dist/` в соответствии с манифестом расширения. Если сборка отсутствует, появится ошибка `missing-build`.

Если достаточно однократной сборки без отслеживания изменений, выполните:

```sh
pnpm build
```

### 3. Установка по Git URL

Укажите адрес репозитория. OpenChamber выполнит поверхностное клонирование и установит расширение. В репозитории уже должны присутствовать собранные файлы:

```text
https://github.com/GuoChen-thlg/git-manage.git#release
```

Суффикс `#release` указывает на ветку публикации, содержащую готовые файлы сборки.

> **Важно**: панель и сервис расширения распространяются в собранном виде. Готовые файлы не включаются в коммиты веток с исходным кодом, поэтому установить расширение напрямую из такой ветки нельзя. Релизы формируются только из основной ветки `main`; ветка `dev` предназначена для разработки и тестирования, а функциональные ветки не публикуются.

## Планы развития

- Сделать профессиональные инструменты визуального управления Git независимыми от конкретного редактора, чтобы удобно работать с ветками и коммитами в любой среде
- Развивать основные возможности как независимые компоненты и постепенно переносить их в OpenChamber, VSCode и другие платформы
- Продолжать совершенствовать интерфейс, ориентируясь на зрелые IDE, чтобы каждое действие было интуитивно понятным
- Развивать проект с открытым исходным кодом и привлекать участников сообщества
